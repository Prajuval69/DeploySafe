# Security and operating limits

- Release inputs are limited to the eight bundled IDs and fixed artifact names. DeploySafe enforces bounded UTF-8 JSON, strict schema and SHA256, canonical root-relative paths, and rejection of symbolic links, Windows reparse points, and hard-linked artifact files. It pins the executable source digest independently of the manifest. Checksums provide integrity checks. Publisher authentication and signed releases are outside the lab's scope.
- The workspace is a filesystem boundary for DeploySafe operations. The trusted fixture processes run with the current user's permissions. Treat the checkout and workspace as private, trusted local files. A user who can modify the Python manager, replace files while it runs, remove kernel guard files, or edit the SQLite schema can bypass its assumptions. Append-only SQLite triggers protect ordinary audit writes and are independent of tamper-proof storage.
- All network operations use 127.0.0.1 and the configured ports within 8000–8999. Health requests bypass proxy settings and redirects. A port bind check detects occupancy before launch, while the HTTP checks and owned-process handles verify startup. The preflight and the fixture's subsequent bind are separate operations, so another local process can claim the port in that interval. Collision or startup failure aborts the attempt. Keep the configured ports dedicated to the lab.
- The dashboard exposes operational history to callers on local loopback. It checks the Host header, escapes audit text, and exposes only read operations. The workspace mailbox is local file IPC. Access to workspace files is the trust boundary for it. Keep credentials and personal data out of the lab.
- Process cleanup uses the guardian's live `Popen` handle. An abrupt supervisor exit closes the pipe, which prompts its guardians to clean up. A simultaneous loss of a guardian and its supervisor can leave an orphan, and DeploySafe refuses to adopt or signal a process from PID metadata. Recovery reports a port collision until the port is free.
- The atomic pointer is reconciled from the last committed SQLite record after interruption. Workspace I/O errors, corruption, or unavailable ports can leave the last committed release offline. Review `status`, `history`, and the runbook before attempting recovery. Status health comes from the supervisor's recent observation. Automatic rollback applies during a deployment transaction, and `recover` performs an explicit check or restart afterward.
- The lab uses a shared host and version-specific loopback ports. Clients check `status` for the current port. A stable traffic address, TLS, authentication, distributed locking, unattended failover, and real traffic routing are outside its scope.
- Evidence and diagnostic files are retained in the workspace. Fixture logs are limited to 64 KiB per instance. SQLite WAL sidecars and supervisor status files also live in the workspace. Use the workspace cleanup instructions after exporting any evidence you want to keep.
